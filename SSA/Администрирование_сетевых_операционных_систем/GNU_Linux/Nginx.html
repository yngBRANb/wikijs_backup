Цель работы: научиться настраивать простой сайт (виртуальный хост).

Краткие теоретические и учебно‑методические материалы

Что такое Nginx

Nginx — высокопроизводительный веб‑сервер и обратный прокси‑сервер. Основные режимы работы:

  • как статический веб‑сервер (отдача HTML, CSS, JS, изображений);
  • как обратный прокси перед backend‑приложением (PHP‑FPM, Python, Node.js и т.д.);
  • как балансировщик нагрузки между несколькими backend‑серверами.

Особенности:

  • низкое потребление ресурсов;
  • асинхронная, событийная модель обработки запросов;
  • удобная система виртуальных хостов (множество сайтов на одном сервере).

Основные директории и файлы конфигурации (типичная схема)

В зависимости от дистрибутива пути могут немного отличаться, но чаще всего:

  • Основной файл конфигурации:
    /etc/nginx/nginx.conf
  • Каталог для отдельных конфигураций сайтов (виртуальных хостов):
    /etc/nginx/sites-available/и/etc/nginx/sites-enabled/
  • Каталог с веб‑файлами (по умолчанию):
    /var/www/html

Задания для лабораторной работы

Установка Nginx:

apt-get install nginx -y

Проверьте статус службы:

systemctl status nginx

Состояние должно быть active (running).

Если не запущен — запустите:

systemctl enable --now nginx

Проверка работы Nginx по умолчанию

Узнайте IP‑адрес вашей виртуальной машины:

ip a

Запомните адрес интерфейса (например, 192.168.56.10).

На хост‑машине (или в браузере внутри ВМ) откройте:

http://<IP_СЕРВЕРА>/

Например:

http://192.168.56.10/

Должна открыться стандартная стартовая страница Nginx (Welcome to nginx…).

То же можно проверить из терминала сервера:

curl http://127.0.0.1/

Если в ответ пришёл HTML‑код приветственной страницы — веб‑сервер работает.

Основные коды состояния:

1xx — Информационные

  • 100 Continue — сервер принял начальную часть запроса, можно продолжать отправку.

2xx — Успешно

  • 200 OK — запрос успешно выполнен, страница/данные отданы.
  • 201 Created — ресурс успешно создан (часто в API приPOST).
  • 204 No Content — запрос выполнен, но ответа в теле нет (например, удаление ресурса).

3xx — Перенаправление

  • 301 Moved Permanently — ресурс навсегда переехал на другой URL (постоянный редирект).
  • 302 Found — временный редирект (ресурс временно по другому адресу).
  • 304 Not Modified — содержимое не изменилось, можно использовать кешированную версию.

4xx — Ошибка на стороне клиента

  • 400 Bad Request — неверный запрос (ошибка в синтаксисе, параметрах и т.п.).
  • 401 Unauthorized — требуется авторизация (нет или неверный токен/логин).
  • 403 Forbidden — доступ запрещён, даже если вы авторизованы.
  • 404 Not Found — ресурс не найден (часто “страница не существует”).
  • 405 Method Not Allowed — метод (GET/POST/PUT и т.п.) не поддерживается для этого URL.
  • 429 Too Many Requests — слишком много запросов за короткое время (ограничение по частоте).

5xx — Ошибка на стороне сервера

  • 500 Internal Server Error — внутренняя ошибка сервера (что-то сломалось в коде/настройках).
  • 502 Bad Gateway — некорректный ответ от другого сервера/сервиса (часто у прокси/балансировщиков).
  • 503 Service Unavailable — сервер временно недоступен (перегружен, на обслуживании).
  • 504 Gateway Timeout — вышло время ожидания ответа от следующего сервера.

Структура конфигурации Nginx

Откройте основной файл конфигурации:

vim /etc/nginx/nginx.conf

Обратите внимание на:

  • директивуhttp { ... }— основные HTTP‑настройки;
  • директивуinclude— подключение конфигураций из других файлов, например:
include /etc/nginx/sites-enabled/*;

Не меняя основной файл, найдите каталог, где хранятся конфигурации сайтов.

ls /etc/nginx/sites-available.d/

Создание собственного простого сайта

Создадим отдельный каталог и простую HTML‑страницу.

Создайте каталог для сайта:

mkdir -p /var/www/example

Создайте файл index.html:

vim /var/www/example/index.html

Пример содержимого:

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Мой первый сайт на Nginx</title>
</head>
<body>
    <h1>Работает!</h1>
    <p>Этот сайт отдан сервером Nginx с моего собственного виртуального хоста.</p>
</body>
</html>

Установите корректные права:

chmod -R 755 /var/www/example

Настройка виртуального хоста (server block)

Создайте новый файл конфигурации, например:

vim /etc/nginx/sites-available.d/example

Вставьте в него:

server {
    listen 80;
    server_name example.local;

    access_log /var/log/nginx/example_access.log;
    error_log  /var/log/nginx/example_error.log;

  location / {
    root /var/www/example/;
    autoindex on;
   }
}

Здесь указано:

  • Listen 80 - порт веб сервера - 80;
  • server_name example.local - адрес сервера на локальной машине и из локальной сети
  • access_log и error_log - путь к логам
  • root /var/www/example/ - путь к каталогу с сайтом на сервере

Создайте символическую ссылку в sites-enabled:

ln -s /etc/nginx/sites-available.d/example /etc/nginx/sites-enabled.d/example

Проверка конфигурации и перезапуск Nginx

Проверьте файл конфигурации на наличие ошибок:

nginx -t

Ожидаемый результат:

nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful

Примените новую конфигурацию, выполнив перезапуск (или перезагрузку):

systemctl restart nginx

Настройка hosts на клиентской машине

Чтобы по имени example.local открывался ваш сайт, нужно добавить локальное имя в файл hosts на клиентской машине (хост‑ОС или самой ВМ, если используете браузер внутри неё).

vim /etc/hosts

Добавьте строку:

192.168.56.10    example.local

(подставьте IP сервера)

Проверка работы виртуального хоста

Откройте в браузере:

http://example.local/

Вы должны увидеть страницу, созданную в /var/www/example/index.html
(«Мой первый сайт на Nginx»).

Можете проверить и через curl:

curl http://example.local/

или (на самой ВМ):

curl -H "Host: example.local" http://127.0.0.1/
