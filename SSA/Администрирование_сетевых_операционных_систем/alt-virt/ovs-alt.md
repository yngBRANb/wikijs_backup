# Практическая работа  
## Настройка VLAN через Open vSwitch на отдельной виртуальной машине в Proxmox VE под управлением ALT Linux

Цель работы

Изучить принципы сегментации сети с помощью технологии **VLAN**, освоить установку и настройку **Open vSwitch** на отдельной виртуальной машине под управлением **ALT Linux**, а также получить практические навыки организации связи и изоляции между несколькими виртуальными машинами в среде **Proxmox VE**.

## Задачи работы

В ходе выполнения практической работы необходимо:

1. Создать в Proxmox VE четыре виртуальные машины:
   - одну ВМ-коммутатор;
   - три клиентские ВМ.
2. Подключить сетевые интерфейсы клиентских ВМ через отдельную ВМ с Open vSwitch.
3. Установить и настроить Open vSwitch на ВМ-коммутаторе.
4. Создать виртуальный мост OVS.
5. Назначить порты клиентских машин в разные VLAN.
6. Настроить IP-адреса в ALT Linux на клиентских ВМ.
7. Проверить, что машины из одной VLAN обмениваются пакетами, а из разных — нет.

## Теоретические сведения

## VLAN
**VLAN (Virtual Local Area Network)** — технология логического разделения сети на отдельные сегменты.  
Узлы в одной VLAN могут обмениваться трафиком, а узлы в разных VLAN без маршрутизации — нет.

## Open vSwitch
**Open vSwitch** — программный коммутатор, который может работать на Linux-машине как полноценный сетевой коммутатор:
- объединять интерфейсы в мост;
- назначать VLAN;
- передавать tagged/untagged трафик;
- обеспечивать изоляцию сетевых сегментов.

## Идея лабораторной работы
В данной работе одна виртуальная машина будет выполнять роль **виртуального коммутатора**.

### Состав стенда:
- **VM-SW** — виртуальный коммутатор на ALT Linux + Open vSwitch;
- **VM1** — хост 1;
- **VM2** — хост 2;
- **VM3** — хост 3.

### Логика VLAN:
- VM1 → VLAN 10
- VM2 → VLAN 10
- VM3 → VLAN 20

Ожидается:
- VM1 ↔ VM2 — связь есть;
- VM1 ↔ VM3 — связи нет;
- VM2 ↔ VM3 — связи нет.

## Топология сети

## Логическая схема

```text
                +----------------------------------+
                |        VM-SW (ALT Linux)         |
                |         Open vSwitch br0         |
                |                                  |
                |  eth1 ---- Port VLAN 10 ---- VM1 |
                |  eth2 ---- Port VLAN 10 ---- VM2 |
                |  eth3 ---- Port VLAN 20 ---- VM3 |
                +----------------------------------+
```

## Подготовка виртуальной среды в Proxmox VE

## Создание изолированных мостов в PVE

Так как OVS должен быть отдельной виртуальной машиной, необходимо организовать отдельные каналы связи между:
- VM-SW и VM1;
- VM-SW и VM2;
- VM-SW и VM3.

Проще всего сделать это через **три отдельные внутренние Linux Bridge в Proxmox**, которые будут играть роль отдельных кабелей Ethernet.

## Зачем нужны отдельные мосты
Если все машины подключить к одному bridge PVE, они смогут общаться напрямую через гипервизор, что нарушит идею работы.  
Поэтому для каждой клиентской ВМ создаётся **свой отдельный внутренний мост**, через который она будет подключаться только к VM-SW.

## Создание мостов

В веб-интерфейсе Proxmox:
1. Выберите узел PVE.
2. Перейдите в **System → Network**.
3. Нажмите **Create → Linux Bridge**.

### Создайте первый мост:
- **Name**: `vmbr10`
- **Bridge ports**: оставить пустым
- **IPv4/CIDR**: пусто
- **Gateway**: пусто
- **Autostart**: включить

Нажмите **Create**.
Аналогично создайте ещё два моста:

### Второй мост
- **Name**: `vmbr11`

### Третий мост
- **Name**: `vmbr12`

## Применение конфигурации
Нажмите **Apply Configuration**.

## Что получилось
Теперь у нас есть три изолированные сети:
- `vmbr10` — линия между VM-SW и VM1;
- `vmbr11` — линия между VM-SW и VM2;
- `vmbr12` — линия между VM-SW и VM3.

## Создание виртуальной машины-коммутатора VM-SW

## Создание VM-SW
Создайте новую виртуальную машину:

- **VM ID**: например `100`
- **Name**: `vm-sw`

Установите на неё **ALT Linux**.

### Рекомендуемые параметры:
- CPU: 2 ядра
- RAM: 2048 MB
- Disk: 10–20 GB

---

## Сетевые адаптеры VM-SW
Для VM-SW необходимо добавить **4 сетевых интерфейса**:

### Интерфейс 1 — управление
- Bridge: `vmbr0`
- Model: VirtIO

Этот интерфейс нужен для:
- установки пакетов;
- удалённого доступа;
- обновления системы.

### Интерфейс 2 — к VM1
- Bridge: `vmbr10`

### Интерфейс 3 — к VM2
- Bridge: `vmbr11`

### Интерфейс 4 — к VM3
- Bridge: `vmbr12`

Если интерфейс при создании был только один, добавьте остальные через:
**VM-SW → Hardware → Add → Network Device**


## Создание клиентских виртуальных машин

## Создание VM1
Создайте виртуальную машину:
- ID: `101`
- Name: `vm1`

Установите ALT Linux.

### Сетевой интерфейс:
- только **один**
- Bridge: `vmbr10`

## Создание VM2
Создайте:
- ID: `102`
- Name: `vm2`

Сетевой интерфейс:
- Bridge: `vmbr11`

## Создание VM3
Создайте:
- ID: `103`
- Name: `vm3`

Сетевой интерфейс:
- Bridge: `vmbr12`

## Проверка схемы подключения
После этого схема должна быть такой:

- `vmbr10`: соединяет только **VM-SW (eth1)** и **VM1**
- `vmbr11`: соединяет только **VM-SW (eth2)** и **VM2**
- `vmbr12`: соединяет только **VM-SW (eth3)** и **VM3**

То есть VM1, VM2 и VM3 **не могут общаться друг с другом напрямую через PVE** — только через VM-SW.

## Настройка VM-SW (Open vSwitch на ALT Linux)

##  Установка Open vSwitch на VM-SW

Запустите VM-SW и войдите в систему.

Обновите список пакетов и установите OVS:

```bash
apt-get update
apt-get install openvswitch
```

Запустите службу:

```bash
systemctl enable --now openvswitch
```

Проверьте состояние:

```bash
systemctl status openvswitch
```

## Определение сетевых интерфейсов на VM-SW

На VM-SW выполните:

```bash
ip a
```

Необходимо определить:
- какой интерфейс используется для управления;
- какие три интерфейса подключены к клиентским ВМ.

Предположим:
- `eth0` — управление через `vmbr0`
- `eth1` — линия к VM1
- `eth2` — линия к VM2
- `eth3` — линия к VM3

> Если имена другие, замените их в командах ниже.

## Создание OVS-моста

Создайте мост `br0`:

```bash
ovs-vsctl add-br br0
```

Проверьте:

```bash
ovs-vsctl show
```

## Добавление интерфейсов в OVS

Подключим три клиентских интерфейса к коммутатору:

```bash
ovs-vsctl add-port br0 eth1
ovs-vsctl add-port br0 eth2
ovs-vsctl add-port br0 eth3
```

Проверьте:

```bash
ovs-vsctl show
```

## Назначение VLAN на порты

Теперь зададим VLAN:

- `eth1` → VLAN 10
- `eth2` → VLAN 10
- `eth3` → VLAN 20

Команды:

```bash
ovs-vsctl set port eth1 tag=10
ovs-vsctl set port eth2 tag=10
ovs-vsctl set port eth3 tag=20
```

Проверим:

```bash
ovs-vsctl show
```

Ожидаемый вывод:

```text
Bridge br0
    Port eth1
        tag: 10
    Port eth2
        tag: 10
    Port eth3
        tag: 20
```

## Настройка клиентских ВМ на ALT Linux

## Настройка IP на VM1

На VM1 выполните:

```bash
ip a
```

Определите имя интерфейса, например `eth0`.

Создайте каталог:

```bash
mkdir -p /etc/net/ifaces/eth0
```

Создайте файл `options`:

```bash
vim /etc/net/ifaces/eth0/options
```

Содержимое:

```text
BOOTPROTO=static
ONBOOT=yes
TYPE=eth
```

Создайте файл `ipv4address`:

```bash
vim /etc/net/ifaces/eth0/ipv4address
```

Содержимое:

```text
192.168.10.11/24
```

Примените:

```bash
systemctl restart network
```

Проверка:

```bash
ip a
```
